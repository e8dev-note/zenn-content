2026-09-22 に Claude Opus 5.5 がリリースされました。この記事は、AI の動きをレビューする人向けの 1 分動画シリーズ「AI を止めるサイン」の Opus 5.5 回のテキスト版です。ニュースの要約ではなく、「モデルが新しくなったとき、何を見て乗り換えを判断するか」の観点で書いています。

@[youtube](ET3eCu3cAbw)

数字はリリース翌日(09-23)に公式発表・移行ガイド・Artificial Analysis を読んで取ったものです。独立評価や開発者の反応は記事・ブログ経由のものが混ざるので、その都度出典を付けます。

## 位置づけ: 上位の性能が Opus の価格帯に降りてきた

![位置づけ](/images/opus-5-5/positioning.png)

一番大きいのは性能そのものより位置づけです。これまで最高性能は上位ティアの Fable 5.1 で、Opus はその 1 段下の実用ティアでした。Anthropic は Opus 5.5 を「ほとんどの作業で Fable 5.1 の水準」と書いています(公式発表)。価格は Opus の帯のまま、さらに値下げ。

## 価格: 全項目 20% 減、キャッシュ読みは 60% 減

![価格](/images/opus-5-5/price.png)

100 万トークンあたり(公式)。

| 項目 | Opus 5 | Opus 5.5 | 変化 |
|---|---|---|---|
| 入力 | $5 | $4 | -20% |
| 出力 | $25 | $20 | -20% |
| キャッシュ読み | $0.50 | $0.20 | -60% |
| キャッシュ書き | $6.25 | $5 | -20% |

Anthropic の主張は「典型的な処理の総コスト -40%、出力速度 +30% 以上」。キャッシュ読みの値下げ幅が大きいので、長いシステムプロンプトや会話履歴を毎回読ませる使い方ほど効きます。

コンテキスト 1M トークン、最大出力 128K は Opus 5 から据え置き。モデル ID は `claude-opus-5-5`(日付サフィックスなし)。

## ベンチマーク: エージェント的な作業の伸びが大きい

公式の数字です。

| ベンチマーク | Opus 5 | Opus 5.5 |
|---|---|---|
| Terminal-Bench 4.0 | 52.3% | 66.4% |
| CursorBench 4.0 | 46.6% | 57.8% |
| FrontierCode v1.1 | 48.0% | 54.4% |
| AutomationBench | 26.9% | 40.0% |
| OSWorld 2.0(コンピュータ操作) | 74.0% | 81.8% |
| GDPval-AA v2.1(知識労働) | 1708 Elo | 1846 Elo |

ターミナル操作と業務自動化の伸びが特に大きく、コードとエージェント作業に寄った改善です。

独立評価では、Artificial Analysis の Intelligence Index が 58(max effort)で 1 位。ただし「数ポイント差」と書かれています。METR のリリース前評価は「Fable 5.1 をわずかに上回る漸進的改善で、不連続なジャンプではない」という結論でした(METR ブログ。METR 自身が、Anthropic が所見の編集レビュー権を持っていたと注記しています)。

## 話し方が変わった

公式の before / after の例が分かりやすいです。バグの説明を求めたとき、Opus 5 はコミットハッシュから説明を始め、Opus 5.5 は影響額から先に言う。重要な情報を冒頭に置き、専門用語を減らし、指定した文章ルールに従う方向に調整されています。

前世代の Opus 5 は「冗長・専門用語が多い・体感が遅い」と開発者の評判が悪かったので、その反動で好意的に受け止められている面もあります。

## ここが本題: 単価と、仕事 1 件あたりのコストは別物

![単価 vs 仕事あたり](/images/opus-5-5/unit-vs-task.png)

Artificial Analysis の計測(max effort)では、Opus 5.5 は **1 タスクあたり約 119,000 出力トークン**を使いました。Opus 5 は約 73,000、Fable 5.1 は約 78,000、GPT-6 Astra は約 27,000。

**出力トークンが 1.6 倍なのに、1 タスクあたりのコストは Opus 5 と同水準**、というのが AA の評価です。

Anthropic の「総コスト 40% 減」と矛盾しているわけではありません。単価が 20% 下がった分を、増えた出力トークンが食っている。どちらの数字を見るかで結論が逆になります。

コードレビュー用途の CodeRabbit の検証も同じ方向で、簡単なバグ 80 パターンではほぼ横ばい(recall 63.8% vs 61.3%)、難しい 13 ケースでは大きく勝つ(76.9% vs 38.5%)一方、トークン使用量はベースライン比 40〜60% 増。「単価が下がってもレビュー総コストが下がる保証はない」と書いています(CodeRabbit ブログ)。

## 既定値が変わった: effort が high → medium

エラーにならない変更のほうが怖い、という話です。

Opus 5.5 では **既定の effort が `high` から `medium` に下がりました**(移行ガイド)。effort を明示していないコードは、モデル ID を書き換えた瞬間に思考量が減ります。エラーは出ません。移行ガイドは、同じ effort でも Opus 5 よりターンあたりの思考量が多いので effort sweep をやり直すことを推奨しています。

もう 1 つ。**ツール呼び出しの間のテキストが、text ブロックではなく thinking ブロックで返る**ようになりました。既定では中身が空なので、進捗を表示している UI は、ツール呼び出しの間だけ黙ります。これもエラーは出ません。

## 開発者向けの破壊的変更は 4 つ

こちらはエラーで気づけます(移行ガイド)。

1. **thinking を無効化できない**。`thinking: {"type": "disabled"}` も `budget_tokens` 指定も 400 エラー。`thinking` を外して effort を下げる
2. **強制ツール使用が非対応**。`tool_choice` の `any` と `tool` が 400。`auto` + strict tool use か structured outputs へ
3. **thinking ブロックがモデルと会話に束縛される**。Opus 5.5 の thinking を読めるのは Fable 5.1 と Mythos 5.1 のみ。ルーターやフォールバックで他モデルに渡すと思考が失われる
4. **`computer_20251124` が Claude API と Google Cloud で非対応**。`computer_toolset_20260801` へ

## 既知の問題: max effort で考えすぎて出力ゼロ

Simon Willison が SVG 生成で 2 回とも 128K の出力上限を推論だけで使い切り、出力なしで終了した、と書いています。Hacker News にも同じ報告が複数あり、「medium が実用上のスイートスポット」という見方が優勢でした。effort は上げるほど良いわけではなく、収穫逓減と暴走があります。

## AI を止めるサイン

![サイン 1](/images/opus-5-5/sign-1.png)

このシリーズの肝です。AI エージェント(や、AI に任せきりのチームメイト)がモデル移行でやりがちなことと、そのとき聞くこと。

| # | AI がやろうとしていること | 何が起きるか | 聞くこと |
|---|---|---|---|
| 1 | 「新モデルのほうが安いので乗り換えました」とだけ報告する | 単価と、仕事 1 件あたりのコストは別物。トークンが増えれば相殺される | 「同じ仕事を 1 件やらせて、出力トークン数は?」 |
| 2 | 移行後にテストせず本番へ切り替える | 既定の effort が high から medium に下がった。指定していないコードは思考量が減る | 「effort は明示した? 乗り換え前後で同じ入力を比べた?」 |
| 3 | 最大の思考量を「いちばん賢い設定」として常用する | 推論だけで出力上限を使い切り、答えが返らない事例が複数報告されている | 「なぜ max? 一段下で足りない根拠は?」 |
| 4 | 移行後、画面がツール呼び出しの間だけ黙る(のを放置する) | 進捗の文章が thinking ブロックで返るようになった。エラーが出ないので気づきにくい | 「移行後、進捗表示は前と同じに見えている?」 |

## モデルが新しくなったとき、見る軸

Opus 5.5 に限らず、次のモデルでも同じ 5 つを見れば足ります。

1. **位置づけ** … 上のティアが降りてきたのか、同じティアの改良か
2. **仕事 1 件あたりのコスト** … 単価ではない。同じタスクを流して出力トークン数を比べる
3. **既定値の変更** … 何も書かなければ挙動が変わる項目はどれか
4. **壊れる場所** … 400 エラーになる変更。移行ガイドの breaking changes
5. **黙る場所** … エラーにならないが出力の形が変わる箇所

## まとめ

- 位置づけは上がり、単価は下がった
- 測るべきは単価ではなく、仕事 1 件あたりのコスト。Opus 5.5 は出力トークンが 1.6 倍で、1 タスクあたりでは Opus 5 と横ばい(AA 計測)
- 既定 effort が medium に下がった。明示していないコードは、乗り換えた瞬間に挙動が変わる
